# Hardening notes — hogee run-8

Hunter hardening notes kept in ledger bookkeeping (not findings; no verdicts). Grouped by hunter.

**h-agent-pay**

- apps/worker/src/rail/xendit-rail.ts:251 uses a denylist (isMockOnlyChannel). Since this range added SGD to XENDIT_CURRENCY_DECIMALS (xendit-rail.ts:38), an SGD request on an unknown channel that reached XenditRail without the router would now be sent to Xendit instead of failing with a RangeError before the call. Every source-visible path goes through PayoutRouter, so this is defence in depth only. Suggest an allowlist in XenditRail: refuse unless payoutChannelOf(channel)?.rail === 'xendit' and the channel's currencies include req.currency.
- apps/worker/src/jobs/settle.ts:111-113,171: for a closed settlement whose binding no longer verifies, the history rail is chosen from the unverified payees.xendit_account_ref, and a PayoutRouteError (NO_ACCOUNT / UNKNOWN_CHANNEL / CURRENCY_MISMATCH) then preempts the SETTLEMENT_CONTRADICTION halt with only a PAYOUT_ROUTE_REFUSED ALERT. Only a DB writer can trigger this, and it can already suppress the halt by other means. Suggest reading a closed settlement's history from every configured rail (the key is unique per settlement), or deciding the contradiction before routing.
- Routability is checked only after the on-chain Spent. packages/core/src/schemas/supplier.ts:71-75 allows any channel with a digits-only accountNumber, but the worker's Account refine (apps/worker/src/rail/rail.ts:68-74) requires a PayNow proxy for SG_PAYNOW. So a supplier on SG_PAYNOW, or on a channel or currency the router refuses, is signed and spent, then either halts the worker every pass (DESTINATION_MISMATCH) or leaves the settlement open with error every pass. Suggest validating the account with the same channel table and facility currency at SupplierApproval/openFacility time.
- packages/agent/src/reader/prefilter.ts:91-97,111-141: the PayNow capture can be evaded. Suggest NFKC normalisation, stripping Unicode format characters before matching, tolerating separators inside a UEN, and treating any proxy-shaped value in a PayNow block (not just the next non-blank line) as a target. No funds can be redirected, because the payout destination is chain-bound.

**h-api-sg**

- packages/api/src/runtime/budgeted-models.ts requestChars/settle measure JSON UTF-16 length, not provider tokens: CJK-heavy prompts cost roughly 1 token per character instead of ~4 characters per token, so the default 30M-character window can admit several times the token spend it was calibrated for. Consider settling with max(chars-based, provider usage tokens x factor) when usage is reported.
- packages/api/src/services/model-budget.ts only raises gateChars when a refused reservation could ever fit; a request larger than MODEL_BUDGET_WINDOW_CHARS/TOTAL_CHARS (possible only if an operator sets the char caps below a long 60-turn chat history, about 250K chars) passes assertOpen every time and leaves one FAILED_CALL llm_calls row per turn, bounded by the chat rate limit. Refusing oversize requests up front (reserve check in assertOpen with the actual size, or a per-call size cap) would close it.
- packages/api/src/services/model-budget.ts gate is sticky on the largest refused reservation: after one large refused call, smaller calls that would fit are refused at assertOpen until the window frees room for the large one. Same-principal availability only (anonymous is the founder), noted for operator awareness.
- packages/api/src/services/exceptions.ts and loosen.ts take WITHDRAW_RESERVE taxPayeeId from the founder's payload and rely on the plan-line isPlatformPayee check; binding it to the server country's catalog tax payee (as ADD_PAYEE does with the catalog, and as api-mock's taxPayeeIdOf does) would make the country separation explicit now that final-1 registers both countries' platform payees.

**h-checks**

- packages/checks/src/sanctions.ts: matching is exact on the normalised name (documented in docs/decisions/checks.md:13), so legal-form or abbreviation variants of listed entities pass, for example 'Korea Mining Development Trading Corp.' vs listed '... CORPORATION', 'Machanga Limited' vs 'MACHANGA LTD', or any appended word ('... Catering', pinned by sanctions.test.ts:50). Consider stripping or expanding legal-form tokens (ltd/limited, corp/corporation, co/company) and a token-subset match that sends near-hits to review.
- packages/checks/src/sanctions.ts: no row-count or content hash pin at load, so a un_sc.csv truncated exactly at a line end loads silently (documented in docs/decisions/checks.md:15). data/sanctions/README.md records 1010 rows; pinning the count or a sha256 at load would turn truncation into CheckUnavailableError.
- packages/checks/src/registry.ts: validateUSCC does not check codes 1-2 or the GB 11714 check inside characters 9-17, and validateUEN accepts any PQ letters. Registry ids are also not tied to the supplier's country (a CN supplier's UEN earns registration trust). No rank impact beyond format-only acceptance, because listing trust is capped at LISTING_TRUST_MAX_BPS < tier2.
- packages/api/src/services/shortlist.ts:31 + packages/checks/src/fx.ts: one getFx per supplier for the same pair and date, with no per-shortlist dedup or per-date cache (9 demo suppliers give 9 to 18+ BNM requests per new spec from the anonymous founder persona; the route has no rate limit). Retries use a fixed 300/600 ms backoff with no jitter and ignore Retry-After. Each call is bounded, but memoising getFx per shortlist (or per date) and adding jitter would cut third-party load and throttling risk.
- packages/checks/src/gleif.ts:51-52: the personal-data probe ignores digit groups joined by an en dash or a period ('+65 9123–4567' passes as a legal name into the GLEIF query string). lookupLEI has no caller at 503cc08; widen the separator class (\p{Pd}, '.', '_') before it is wired into a shortlist.

**h-core-sg**

- CountryPack (packages/core/src/schemas/country-pack.ts) does not bind `currency` to `countryCode`, so an SG pack labelled MYR would parse. compilePlan's facility/pack currency check plus the API's currencyFor(HOGEE_COUNTRY) check (packages/api/src/services/compile.ts:111-122) catch this on the compile path. landedCostFromPack (shortlist) has no such check. A per-country currency rule in the CountryPack refine would make a mislabelled pack fail at load. This is operator data only.
- fileCatalog.loadPack (packages/api/src/runtime/catalog.ts:47-55) does not check that the parsed pack's countryCode equals the requested `cc`. compilePlan catches a mismatch (COUNTRY_MISMATCH), but the shortlist's landedCostFromPack would use a mislabelled <CC>.json's facts. Operator-controlled data, no attacker path.
- RegistryPayee (packages/core/src/constitution/types.ts) carries no country, so compilePlan cannot itself keep the other country's final-1 platform payees out of a plan. It relies entirely on the API passing a per-country registry (catalog.payees() = demoPayeesFor(HOGEE_COUNTRY)). An optional country tag checked against facility.countryCode in payeesForLine would make that a core-side defence-in-depth check.
- landedCostFromPack prefers a caller-supplied mfnDutyRateBps over the pack's sourced per-category rate (packages/core/src/landed-cost/index.ts:196). No caller passes one today. If one is added, its source should be recorded in the landed-cost rule, because the compiler's MFN rule cites only the pack leaf.

**h-mock**

- packages/api-mock/src/evidence.ts evidenceRuns has no run-count cap. Live caps at MAX_LISTED_RUNS=200 newest by folder mtime (packages/api/src/evidence/store.ts:22,111-127; run-6 v-2). findRun (evidence.ts:179) makes every getEvidenceRun, getEvidenceFile and exportEvidence request re-read and zod-parse every run's manifest.json and evidence.json (<=4 MiB each) with synchronous fs calls on the Next event loop. Live reads only the requested run. The run count is operator-written (the mock's exportEvidence writes nothing), so no anonymous input grows it. Add the same cap and look up a run by folder name.
- packages/api-mock/src/evidence.ts lists bundles of any facility, deployment and chain under <repo>/evidence: there is no contracts.json tenant check (live store.ts:96-97). It includes the exporter's hidden .export-* temp folder while it is written (live isRunName skips dot-names) and serves a bundle under its manifest runId rather than its folder name (live requires both to match). Red-team output is never listed (no manifest.json), but its evidence.json is read on every request. README.md should state which bundles MOCK_API=1 exposes.
- packages/api-mock/src/evidence.ts evidenceFile allocates and synchronously reads up to 32 MiB per request (readUpTo). This matches live's cap, but blocks the shared Next event loop for the read.
- A wallet-signed FOUNDER_SIGNED loosening records no signer (signing.ts:327), so officer approval re-checks neither HOGEE_MOCK_OWNER_EOA nor the role-address clash. This is reachable only through operator env changes. A discriminated signer record fixes it together with the candidate.
- Rejecting a pending key does not cancel loosenings it signed that the officer already queued while it was pending: founderKeyFor trusts pending keys (store.ts:230-235, documented 'applies at once'). The officer must veto them manually during the timelock.
- packages/api-mock/src/seed.ts readFixture reads evidence/<runId>/scenario/* in REPLAY mode with existsSync+readFileSync. It follows links and has no size cap. This runs at startup or state build on operator data, not per request.

**h-privacy**

- packages/agent/src/guard/redaction.ts json(): a nested object takes its own key as context and drops the parent's, so {"phone":{"number":"91234567"}} or [{"type":"mobile","value":"91234567"}] keeps a bare SG phone (guard.test.ts:111 shows contactPhones:[..., {note}]). No planner tool returns PII today; pass the parent key context down, or join parent and child contexts.
- data/pii/recognizers.json phone patterns need '+', '00' or a bracketed country code, or a context word, so E.164 without '+' is never redacted. Examples: a JSON number 6591234567 or 60123456789 under a 'phone' key, and wa.me/6591234567 links in listings.
- data/pii/recognizers.json SgPhoneRecognizer context list lacks 'paynow', 'number', 'ph', 'mob' and 'telegram', so 'PayNow 9123 4567' and 'my number is 9123 4567' are not redacted, and phones are not in the canary. Relevant now that SG/PayNow is the main country.
- data/pii/recognizers.json MyBankAccountRecognizer requires 10-16 digits and has no 'dbs' or 'posb' context word, so 9-digit SG POSB accounts are never redacted. SG bank accounts are not a claimed entity (architecture lists MY bank accounts only).
- data/pii/recognizers.json MyPhoneRecognizer has no bracketed-area-code pattern, so a Malaysian landline '(03) 1234 5678' is not redacted even with 'tel' context (IdPhoneRecognizer has one for Indonesian numbers).
- packages/privacy/src/config.ts compileRecognizers accepts hogee_context_required: true on a recognizer whose context list is empty. wordRegex returns null, so that pattern silently never fires; the schema should refuse the combination, as it fails closed elsewhere.
- The key-context pass in packages/agent/src/guard/redaction.ts withContext counts the key only when it falls within the recognizer window (32 characters before, or 48 for bank accounts), so a long string value under a 'phone' or 'account' key loses its context beyond that point.
