# Hardening notes — hogee run-6

Hunter hardening notes kept in ledger bookkeeping (not findings; no verdicts). Grouped by hunter.

**h-evidence**

- packages/api/src/evidence/collect.ts 46-51 exports raw_signed_tx whenever tx_hash is set, but writeSigned in packages/chain/src/targets.ts 192-205 sets tx_hash at signing time. So SIGNED, BROADCAST, DROPPED and CANCELLED payment rows, and PENDING chain actions with stored bytes, ship their raw bytes. This contradicts the collect.ts comment and docs/G0-DECISIONS.md section 10 ('raw signed tx once mined'). No boundary impact found, because the worker never withholds or cancels a row's own stored bytes. recoverOpenIntents (reconcile.ts 61) re-sends them on every pass, even while halted. The no-op cancels in nonces.ts 241-275 fill only nonce holes that no row owns. CANCELLED requires the nonce to have been consumed by a foreign tx. Superseded bytes are tracked in superseded_tx_hashes. A reader can therefore only broadcast early. h-verifier reported the same lead and was answered. Fix: use MINED_PAYMENT_STATES / MINED_ACTION_STATES from fetch.ts as the predicate.
- llmCallSink records eval LLM calls during the model call, before the eval trace event is written. An eval that throws or aborts before its first eval event (eval-plan.ts 110-111, eval-case.ts 225, eval-shortlist.ts 99-101) leaves llm_calls rows whose trace_id has no trace. collect.ts 157 does not exclude them, so they appear in llm-calls.json and in the SUMMARY count, and audit.ts 41-49 accepts orphan calls. The data is hash-only and the routes are demo-only. Fix: exclude llm_calls whose trace_id has no non-eval trace, or write the eval trace event before the call.
- collect() runs each query on a separate pool connection (rows in sql.ts on the Pool) with no shared snapshot. A bundle can therefore mix states, for example a payment without its trace or rationale, fail self-verification and still be marked READY. Fix: run collect in one READ ONLY REPEATABLE READ transaction.
- export.ts 157-177 builds every file, hashes.json and SUMMARY.md in memory before the 128 MB / 32 MB checks run, and verifyBundle (export.ts 239) and hashesFileOf run synchronously on the API event loop. Fix: reject on running totals while building, and move self-verification off the request process (to a worker thread or the CLI).
- In store.ts readInside (29-37), realpath(full) and the later lstat/open are separate path lookups. A parent-directory swap between them is not caught by the dev/ino comparison, because both lookups follow the swapped parent. fh.readFile() is also not limited to the fstat size. Only a local writer of the evidence root could exploit either. Fix: open the run directory once, walk components with no-follow, directory-relative opens, and read at most the verified size.
- signatures.json exports the verified founder submission for SUBMITTED requests whose relay is still pending or was refused by the relay-calls.ts checks. commitPlan, bindPayee and releaseMilestone accept founder-signed structs from any sender by design ('anyone may submit'), so this is not a bypass. Exporting a submission only once its chain action is mined would still keep unrelayed authorisations private.

**h-verifier**

- read-dir.ts:34,51 builds `files` as a plain object. A top-level bundle entry named '__proto__' sets the object's prototype: it is silently dropped instead of being flagged as an unexpected file, and load.ts:84 (`path in files`) then consults that prototype chain. Use Object.create(null) or a Map with Object.hasOwn.
- chain.ts:122 accepts a pre-EIP-155 tx (chainId null) for any chain id.
- The row `nonce` (bundle.ts:131) is never compared with the signed tx's nonce (crypto.ts:118).
- Trace hash chains and the LLM call log are self-hashed with no anchor: not in any rationale preimage, not on chain. Recomputed traces verify, and a payment's traceId does not have to appear in traces.json (audit.ts:80 checks evidence rows only). Consider committing the trace head hash inside the rationale preimage.
- T-row outcomes (audit.ts:61) rest on the row's revertReason claim. SUMMARY.md:50-51 discloses this, but the CLI prints 'ok evidence rows' without saying reason-based outcomes are unverified offline.
- plans.ts:154-157 flags a missing PlanCommitted only for COMMITTED/SUPERSEDED. A plan labelled PENDING_SIGNATURE (or another status) whose PlanCommitted event is present is not flagged.
- plans.ts:173 checks the first commitPlan action of a plan row, which may be a reverted earlier attempt; the mined commit's calldata and signature pairing is then not checked.
- cli.ts:52: a missing directory argument throws and exits 1 instead of the documented 2 (still non-zero). latestBundle (cli.ts:28-36) ranks bundles by the self-declared contracts.json exportedAt.
- Disproved leads: the EIP-712 domain name and version are pinned by core Eip712Domain literals (packages/core/src/schemas/signing.ts:46). PlanReplan requires the same line set and allocation on a re-commit, so replay.ts:71 keeping the prior allocation matches Treasury._syncLine.
- Cross-unit lead sent to h-evidence (export data leakage): collect.ts:47-51 exports raw_signed_tx once tx_hash is set, and writeSigned (packages/chain/src/targets.ts:191-213) sets tx_hash at signing time. h-evidence had already recorded it as hardening; reconcile re-sends the same bytes, so it found no boundary impact.

**h-writers**

- packages/chain/src/passkey/encode.ts publicKeyFromSpki checks only the 0x04 byte at len-65. It does not check the P-256 SPKI header (id-ecPublicKey + prime256v1) or that (qx,qy) is on the curve, so a wrong-curve or garbage SPKI yields a key that only fails later at verification (self denial of service; OZ P256.isValidPublicKey and Node createPublicKey reject off-curve points). Compare against the fixed 26-byte P-256 SPKI prefix and check the curve equation before enrolment uses it.
- packages/chain/src/passkey/encode.ts assertChallengeMatches checks the JSON.parse view (last duplicate key wins, escapes decoded). OZ instead compares raw bytes at the first '"challenge"' offset that clientDataIndices computes, so the optional pre-check can disagree with the chain in either direction. It is denial of service only, since HogeeSigs and the API verifyPasskeyAssertion re-verify byte-exactly. Make the pre-check the same raw-substring comparison at the computed indices, and make digest mandatory in encodeWebAuthnAuth for relay paths.
- packages/chain/src/passkey/encode.ts encodeWebAuthnAuth decodes clientDataJSON with TextDecoder's default ignoreBOM:false, which strips a leading UTF-8 BOM. The re-encoded clientDataJSON then no longer hashes to what the authenticator signed (fails closed). Use { fatal: true, ignoreBOM: true }.
- packages/db/src/rationales.ts insertRationale trusts that rationaleHash === hashObject(rationale) and that salt is null. Writers compute both together today, but a defensive equality check, which would throw inside the decision transaction, would make a future mismatched caller fail closed at write time instead of producing a bundle that fails verification.
- Worker rationales PACING_SLOT, MILESTONE_FUNDING and OFFICER_OVERRIDE leave decisionId out of the preimage, while API SPEND_PROPOSAL and FOUNDER_MILESTONE_RELEASE include it. Identical worker rationales therefore share one rationales row (on conflict do nothing keeps the first decision_id), and the exporter nulls decisionId. Their decision binding rests only on payment rows and events, not on the commitment.
- packages/core/src/compiler/compliance.ts resolveEntity still uses a code heuristic ('compiler:entity', FOREIGNER_ENTITY) when the pack has no entities entry. This is a labelled assumption outside the PackLeaf list and inconsistent with 'nothing is assumed in place of a missing fact'. It affects which registration is required, but the fees still fail closed. The MFN duty rule without dutySources is text only and carries no amount.
